Released 2026-07-03

CI and release automation baseline

This release adds the first durable release communication channel and a scheduled staging E2E safety net for the most important production workflows.

Highlights

  • Published public release notes through GitHub Pages.
  • Added a manual release notes workflow for the current release process.
  • Added a scheduled staging Playwright workflow for deployed-environment checks.
  • Added a read-only dashboard smoke test covering login and core tab navigation.
  • Kept the existing award-points E2E path as the primary mutating workflow check.

Fixes

  • Hardened Auth0 E2E selectors so social-login buttons do not conflict with the primary Continue action.
  • Hardened point-award E2E selectors so the +5 point button does not conflict with +50.
  • Adjusted Pages publishing so the workflow enables GitHub Pages at runtime before deployment.

Operations Notes

  • The staging E2E workflow uses the GitHub Environment named staging.
  • Required staging secrets are E2E_BASE_URL, E2E_USER_EMAIL, E2E_USER_PASSWORD, and E2E_TARGET_MEMBER.
  • The release notes workflow publishes the committed site directory to GitHub Pages.
  • Semantic-release remains deferred, but the future template and automation notes now live under tools/release.

Verification

  • Staging E2E workflow completed successfully.
  • Release notes GitHub Pages workflow completed successfully.
  • npm.cmd run lint passed for repo-level lint coverage.
  • git diff --check passed for whitespace validation.

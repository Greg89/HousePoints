Released 2026-07-10

Usability and Admin Tools Improvements

This release improves high-traffic account and member workflows with better dropdown behavior, clearer release notifications, persistent release notes access, and an admin tool for helping members update display names.

Highlights

  • Improved member dropdown behavior for point award and deduction flows.
  • Added release notification management so What's New announcements can be marked read and archived cleanly.
  • Restored the persistent What's New link in the account dropdown.
  • Added an admin member rename tool for updating display names inside an organization.

What's New

  • Large member lists are easier to use in dropdowns and should no longer run past the bottom of smaller laptop screens.
  • Release announcements behave more like normal notifications after users read them.
  • The account menu now keeps a stable What's New entry so users can revisit release notes even after the notification is gone.
  • Admins can help members fix confusing or incorrect display names without asking for a database edit.

Operations Notes

  • The production web app should have APP_RELEASE_NOTES_URL configured so the persistent What's New link is visible.
  • The production API and GitHub Actions should share RELEASE_AUTOMATION_SECRET before recording or broadcasting this release.
  • The GitHub repository variable RELEASE_RECORD_API_BASE_URL should point at the production API base URL without a trailing endpoint path.
  • Record the release first, verify production health, then broadcast the notification to active users.

Verification

  • CI validation passed before production release.
  • Staging E2E should pass before broadcast.
  • Production deployment should be healthy before enabling broadcast_release.
  • After broadcast, verify the notification appears in the account menu and links to this release note.
